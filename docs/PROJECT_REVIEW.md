# 简历工坊项目评估与优化建议

评估日期：2026年10月20日

评估对象：项目根目录。本次检查源码、文档、启动脚本、构建、测试和公开开源项目资料；没有读取个人简历材料正文，也没有把项目发布到公网。

## 结论

项目已经是一套可运行的本地简历编辑器 MVP，适合继续作为个人中英文简历工具迭代。当前更需要提升导出可解析性、数据一致性和维护效率，再增加模板与 AI 工作流。

保留纯静态、本地优先架构。现阶段沿现有 ES modules 拆分职责即可；云账号、多租户数据库等能力会增加部署和维护成本，可留到确有跨设备协作需求时再引入。

## 现状

| 方面  | 代码中的实际能力                                     | 主要限制                                                                                                                      |
| ----- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 编辑  | 中英文档案独立，教育、实习、项目、技能，实时 A4 预览 | 状态/迁移/编辑/简历库/预览/导出已拆到 `src/lib/`，`app.js` 只做接线                                                           |
| 版本  | 多份简历库，切卡预览与修改分离，版本快照             | 主要依赖 localStorage，照片重复保存可能挤满容量                                                                               |
| 照片  | 上传、裁切，同步到双语与全部简历条目                 | 同步语义是项目既定约定；未来新增个人档案前需重新设计照片归属                                                                  |
| 导入  | JSON、DOCX、TXT、Markdown                            | Word 是分区识别，不保留原始版式；PDF 正文暂不导入                                                                             |
| 导出  | 图片版 Word、可编辑 Word、图片型 PDF、PNG、JSON      | 图片版视觉一致，但没有正文文本层；可编辑 Word 版式近似                                                                        |
| 字体  | 本机字体设置、参考 PDF 字体名称记录                  | 字体名相同不足以证明字形、字号、间距和分页完全相同                                                                            |
| Agent | 本地 CLI、可选本地 API、候选 JSON 校验与备份         | 浏览器与 Agent 共用 `src/lib/schema.js` 的 `normalizeState`；Agent 侧只保留项目排序、标题和风险词提醒；写入文件后仍需页面导入 |
| 工程  | 构建、CI、浏览器冒烟测试、文档和演示数据隔离         | 目录当前没有 .git；已覆盖简历库、头像显示与五种实际下载；尚缺导入往返、英文内容和长文分页回归                                 |

Reactive Resume 的官方说明列出浏览器后台 PDF 渲染、字体预设、内容溢出调整及多种导入导出能力。OpenResume 的官方说明强调本地隐私、实时 PDF 与解析器。这些方向与当前项目需求更相关，优先级高于复刻所有商业站功能。

## 优化顺序与验收

| 优先级       | 工作                          | 原因                                                        | 建议验收条件                                                                                                         |
| ------------ | ----------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| P0           | 新增带文本层的 PDF 导出选项   | 当前图片型 PDF 无正文文本层，不适合文本选取、检索和直接解析 | 中文和英文可选取、复制、搜索；抽取文本包含姓名、公司、日期、技能；保留现有图片版                                     |
| P0（已完成） | 统一浏览器与 Agent 的数据校验 | 目前存在字段、上限和处理策略分叉的风险                      | 同一 JSON 在两个入口得到相同规范化结果；非法字段与超限给出明确提示                                                   |
| P0           | 扩展导出与数据往返测试        | 菜单存在不等于每种导出都正确                                | 已有文件名、格式与头像检查；继续补充选中卡片尚未进入编辑时的导出、英文内容、双语 JSON 导入往返及坏文件不覆盖已有数据 |
| P1           | 按内容块分页                  | 当前画布按A4高度切片，长简历可能从文字中间切开              | 用两页中文、两页英文和大照片样例检查标题与内容、列表行均不从中间截断                                                 |
| P1           | 字体预设与参考核验            | 依赖本机字体会导致不同设备版式变化                          | 记录字体来源、版本、字重与字号；导出后检查实际嵌入字体及逐页视觉对照；合法使用字体资源                               |
| P1           | 拆分 app.js 职责              | 格式化提升可读性，仍未解决职责集中                          | 先抽纯函数和状态持久化，再拆简历库、照片、预览、下载；每次保留现有回归测试                                           |
| P1           | 照片与简历分开存储            | localStorage 容量有限，相同照片在多版本重复占用             | 照片存 IndexedDB，以 photoId 引用；迁移失败时仍能读原存储，不自动清空旧数据                                          |
| P1           | 本地服务边界                  | Agent API 面向本机工具，应有清晰调用边界                    | 校验 Host/Origin、限制内容类型与请求体、原子写入和备份；默认仍为纯静态编辑器                                         |
| P2           | JSON Resume 适配              | 提高跨工具迁移能力                                          | 现有 v1 与标准格式能转换；不支持的字段进入扩展字段并明确提示                                                         |
| P2           | JD 与专业词库工作流           | 将现有职业词库变成有依据的岗位定制                          | 每个建议可追溯 JD 来源，明确已有证据与待补充信息；用户可逐项接受，不自动编造指标                                     |

建议第一阶段只做 P0 三项。文本型 PDF 是新增能力，需要明确调整当前 AGENTS 中“视觉导出是图片型”的边界；不要在未更新约定时直接替换现有图片导出。

## 建议代码边界

```text
src/
  app.js                 启动与连接模块
  state/
    storage.js           存储键、读写、迁移
    schema.js            浏览器与 Agent 共用规范
  features/
    library.js
    editor.js
    photos.js
    terminology.js
  render/
    resume.js            单一纸面渲染入口
    pagination.js
    fonts.js
  exports/
    json.js
    docx-editable.js
    visual.js            现有图片型 Word/PDF/PNG
    pdf-text.js           新增文本型 PDF
```

先抽取无 DOM 的纯函数，避免一次性重写。是否引入 TypeScript 可在边界稳定后决定。

## 本地部署与日常命令

本次使用4180端口，避免占用之前编辑器的4173端口。localStorage 按域名和端口隔离，新端口不会自动读取旧端口数据；需要时用 JSON 导出后导入。

```bash
cd resume-studio
npm ci
npm run verify
npm run build
npm run preview -- --port 4180
```

本地地址：`http://127.0.0.1:4180`。只绑定本机，不向局域网开放。
